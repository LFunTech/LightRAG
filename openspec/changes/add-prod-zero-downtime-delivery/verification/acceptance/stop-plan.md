## 标准停止步骤

下文`STOP_REQUESTED`是**人工/观测侧的独立停止记录分类**，不是新增release phase，也不表示工具已实现该事件自动落盘。不得手工编辑attempt journal、数据库phase/owner或原控制证据来制造该状态；实际触发/停止时间另外保存在批准的私有事故记录中。

1. **记录STOP_REQUESTED**：记录UTC、run/输入SHA、phase/epoch、触发分类和最后可知状态；无法写盘时停止并以批准的第二受控渠道报告“证据无法保存”，不要推断未发送/未执行。
2. **停客户端新工作**：停止load新arrival和未发送typed动作、冻结依赖链、停止新的控制advance/故障注入。不要新增业务/缓存预热、请求重试、负载延长或“验证性”写探针。
3. **保留正在进行的控制动作**：已开始的原子advance可能已改变路由/交权，不强制取消。等原有限调用返回后只读核对实际阶段，下一步不再自动推进，不用本地记忆或返回超时假定没有切换。
4. **结算已发请求**：HTTP client保持打开，等待已发写/读/长流在批准预算内自然结束。正常取消只触发合作停止，重复取消不能取消owner中的已发写；随后关闭客户端资源并传播取消。SDK已打开的流须按原合同exhaust/aclose。
5. **显式区分状态**：未发送为NOT_SENT；已持久队列、执行中、原业务受理和业务终态分别记录。HTTP超时/断开、Pod/Job消失或仅剩SENDING时记真实未知，不记成FAILED未执行，不重投同业务mutation。
6. **只读核对并通知**：在仍获准的观察范围保存实际路由/CLB、各实例、owner/epoch、queue/oldest/ticket与coordinator active/pending/claim/lock/witness、后台/后端在途和源引用；读取失败保持unknown。快照不取代原控制面的排空判定。
7. **人工决定后续**：保留owner、Job、Pod和持久证据；当前run不通过/未完成。是否条件中止/回退、重新开始新run或清理fixture，必须由批准决策人根据现场再授权；不能把一次“暂停”当恢复许可。

**停止客户端不等于冻结服务器全部写入。** 有权executor可能继续处理已接收QUEUED命令，已启动文档任务/后台写也可能完成；正常停止不主动改gate、不停polling、不调用cancel_pipeline、不撤销业务授权以伪造排空。记录这些尾部效果并预留模型/存储费用、对象保留和实例资源。

若客户端硬超时后后端仍可能写，关闭客户端不能证明backend=0；保留UNCERTAIN/原mutation与归因证据，不能退休实例/释放writer屏障。无法保证有限尾部资源和可达人工处置时不启动测试；不能用SIGKILL或数据库重启保证预算封顶。

## 按发布阶段处理

| 停止位置 | 当前run动作 | 另行处置门禁 |
| --- | --- | --- |
| 尚未取得owner | 不开始发布/发压，保留失败预检记录 | 修正参数/证据后重新批准新run，不创建资源“试试看” |
| PREPARED/DRAINING/READ_SWITCHED | 停新工作，保留Blue/Green和实际路由/队列；不自动开闸或abort | 交权前仅当Blue真实路由/写权确定、无未知写且已获专门授权，才可调用原安全abort路径；ABORTING须等standby关闭/回收确认 |
| WRITER_SWITCHED/RETIRING | 保留Green现有服务与Blue旧连接，后续推进暂停；不强删实例 | 反向交接必须独立批准兼容证据/from-to digest/profile/排空；Blue已开始退休/发布完成不能直接复活旧二进制 |
| COMPLETED后发现质量/容量失败 | 记录真实完成阶段与验收失败，不篡改owner/历史 | 不将COMPLETED等同SLO/领域质量通过；另案评估新发布/修复，不直接undo |
| control Job/机器失联或磁盘丢失 | 承认结果未知，从持久状态只读调查；不自动拉起runner续跑 | session锁失去不释放持久owner；存在SENDING/EXECUTING/UNCERTAIN须先审计，不可复制journal重放 |

原普通delivery runner对明确排空预算可能有受控安全中止分支；本次隔离rehearsal使用逐步advance，不把普通runner的行为解释为本预案允许自动abort。任何recover、force_reset、清锁/fence、直接改控制表、重启PG、还原单边备份、rollout undo或强杀Pod均不属于本预案。

## 动态usage与混合停控接线（仅本地实现，2026-10-23）

rehearsal v2增加共享停止事件与独立有界观察器：按实际Pod UID、slot、digest、config/profile、进程epoch持续采集4→8→4。成员无解释消失/替换、身份或计数漂移、terminal unknown、采集超时/预算耗尽/写盘失败均阻断新增读写、质量探针和下一次advance；超时先置停发，再join尚在收尾的只读采样。已开始的原子advance不强杀，但退休缩容前还必须通过最终证据gate。

旧Blue监听关闭后不再依赖HTTP取末量。应用正常排空及存储finalizer结束后，先写≤3500字节终止摘要并fsync，再发送既有closed ACK；观察器联合该行六项0、Pod UID/固定配置/镜像和exit=0验证。四份final证据及journal在受控目录落盘后才允许原transport缩容。仅即刻前次exit=0且restartCount=1可作为原process证据；其他重启、截断、缺失、非零退出或未排空均停。不会修改原SQL/schema、写权或权限，普通发布不被当作已取得本工具的usage证明。

已发送的写/查询/长流保留原有有界超时；已受理写仅允许必要GET追踪/读回，未知ACK记UNCERTAIN，不补发mutation。重复调用者取消会等待收尾再传播；停止不改服务端gate、不recover、不重启/清owner、不自动清理。joining/closing不补0，保留最后已知量及partial标记；即便新工作已停，服务器已受理写仍可继续，必须保留尾部资源/费用和未决义务。

五项动态采样/证据预算仍为空；底层K8s/HTTP/PG只读超时、fsync/线程join的尾部以及client_drain_deadline须共同审查。超时是停发deadline，不承诺强杀I/O封顶总收尾时间。本工具不是外部资源/SLO/账户额度告警全接线，也不合并跨Pod延迟分位或替代账单。原test和两个候选均未改动，真实4+4/CLB/容量复测另行确认。

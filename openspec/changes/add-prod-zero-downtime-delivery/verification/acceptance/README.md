## 已确认值与不可推导项

- 目标为**1000 QPS完整RAG，包含最终模型生成**；约10000在线用户。QPS仅指查询到达率，写操作频率另填；在线人数不能代替`max_inflight`。
- 生产起步为4个应用Pod、每Pod1 worker；蓝绿Blue4+Green4共8个应用Pod。隔离容量矩阵另含单Pod基线；不将真实prod缩为1Pod。
- 入口家族为qcloud。代码目前只支持HTTPS七层/CLB直连Pod/HTTP后端profile；**真实目标是否符合尚未核验**，不据入口名称填写CLB参数或连接保持结论。
- 当前实现的prod策略关闭完整答案缓存、保留抽取恢复缓存；这不是现场开关观测值。测试必须记录实际解析配置和hash，不擅自打开答案缓存或清抽取缓存制造冷态。
- 2026-10-22用户确认7项数值目标：Query Embedding、向量检索、Rerank、检索全链路、RAG首Token、完整响应及检索成功率。已记入`parameters.json.slo`；[指标目标与口径](metrics.md#用户确认的性能目标2026-10-22)列出对应关系和待确认项。数值确认不等于统计口径、全部参数或执行授权获批，更不是实测达标。
- 用户后续确认技术成功与相关性分别验收，合法空结果可计技术成功；相关性阈值/真值仍待确认，不能用空结果虚报完整生成吞吐。Rerank不是必选，保持当前关闭profile，200ms仅在未来显式启用时适用。写排队最大值由用户授权代选，规划为30s；理由及超预算不丢弃/重放已受理写的边界见[指标文档](metrics.md#写排队30秒的规划依据与边界)，不是已生效配置。
- 未确认的SLO、其余负载参数、时长、模型、CPU/内存、额度、namespace/UID、预算与审批全部保留`null`。仅明确授权代选的写排队30s和下述4项负载基线填值；代码安全上限不是业务SLO，12类整体/执行批准仍false。
- 用户另行授权的[直方图边界子切片](../histogram-local-results.md)已补齐应用/客户端0.2s、3s、20s分桶并完成本地验证；只改变可选观测的分桶，不启用采集、不修改本底稿或现有test配置，不代表外部遥测/真实容量已通过。

## 授权代选的负载基线与模型清单核对（2026-10-22）

这是一组**经验合成规划值，不是真实业务统计或可执行负载批准**。数值来源为`parameters.json.workload`，代选范围在`acceptance_decisions.workload`登记；只填写4个原空字段，该次v4快照为191个待定参数叶子；本轮v5只新增5项空观测预算，当前196项，12类批准仍false。

| 项目 | 本次规划值 | 边界 |
| --- | --- | --- |
| 流式占比 | 80% | 其余20%为非流式；不改变1000完整RAG QPS口径 |
| 多轮占比 | 30% | 与流式可重叠；只定边际比例，不假装已核验联合分布 |
| 最终生成输入 | 4096/8192/16384 Token，权重25%/50%/25% | 包括system、问题、检索上下文与历史总输入；历史不重复加算；离散均值9216，规划P50=8192/P95=16384 |
| 最终生成可见输出 | 256/512/1024 Token，权重25%/50%/25% | 离散均值576，规划P50=512/P95=1024；不含未知模型的隐藏思考Token或重试 |

选择80%流式以覆盖首Token/长连接压力，保留20%完整非流式；30%多轮用于覆盖历史旁路与更长prompt。这些权重不是行业统计。既有生成器使用两个确定性序列，短run实际比例和联合分布仍须以冻结数据/输入及实测计数为准；超长输入/长流、冷/热/热点、读写混合等独立场景不被此基线免除。

Token值是未来合成样本的**目标长度**，不是把`max_tokens`参数当实际输出，也不表示已准备了匹配数据集。后续需按确定模型/实际Tokenizer验证输入长度、上下文上限和usage；若不支持该长度，应先评审修订基线，不静默截断或用占位/空结果充完整生成。`max_total_tokens`、在途/时长、读写比、其他SLO/预算等未被本次授权代选，仍为空；不自动修改`workload-target.json`、运行配置或生成可执行plan。

**仅最终生成的算术需求：**按1000 QPS、每查询至少一次最终模型调用，基线需要60000次/分钟；按上述离散均值为552960000输入Token/分钟、34560000可见输出Token/分钟。这是规划需求，不是账号可用额度或实际吞吐，不含关键词/Embedding/入库/其他调用者/隐藏思考/重试/Green私有验收的额外预算，不能据此填写模型并发或Pod容量。

**prod清单核对结果：**在用户指定的`.secrets/prod.secrets`中可识别API Host/API KEY等凭据字段，未列明确的生成/关键词/Embedding型号、revision、维度或RPM/TPM/并发额度字段。只核对字段结构和允许公开的元数据，不保存凭据/端点值、不执行文件、不读取test清单、不调用账户/模型；不从网关Host、密钥或test默认配置推断模型。因此`resources.models`保持原有空值，`model_metadata_inspection`记录“缺少明确字段”，不是连通性或额度核验通过。

公开的[模型限流说明](https://help.aliyun.com/en/model-studio/rate-limit)仅作RPM/TPM口径参考，不证明当前提供商身份或本账号额度。若型号位于另一份配置，需要其明确路径；额度须来自已授权的账号记录/只读核验，不能把公开默认限制当账号获配能力。

## 从底稿到可执行输入的门禁

1. `parameters.json`只是**不可执行的审批底稿**，不符合现有load/rehearsal CLI schema，不得直接传入`--run`，也不能把`null`替换为0、无限值或test默认值绕过校验。
2. 参数和每项操作范围取得明确批准，保存批准人/版本/时间的受控记录；JSON中填写审批编号不是自行产生授权。无需提供密钥正文，源码只保存非敏感参数或私有证据引用。
3. 根据批准底稿分别生成严格的read plan、typed mixed plan、golden/scenario及原交付输入；引用[现有工具合同](../../../../../scripts/performance/rehearsal.md)。它们需在私有新目录离线验证并冻结输入SHA，再申请真实执行。
4. 核算`ceil(QPS×duration)`不能被`max_requests`截断；read/mixed/observer/CLB控制预算独立且合并计费。混合runner读请求≤600秒/计划≤24小时、受限动作≤100等只是代码安全边界，不是本次批准的时长或写压力。
5. 校验`drain+cutover+safety_margin < request_wait`，`request_wait+response_margin < min(proxy_timeout,client_timeout)`；保留窗口覆盖排队/执行/读取。长流尾部和请求硬超时也必须相容。所有4/8Pod共享额度及其他调用者计入，缺项不启动。
6. [完整写入口](write-entrypoints.md)中没有自动工具支持的项目不能标“已验证”；补独立受控用例/适配并单独评审，或基于实际配置证明不适用。必要计量/审计可靠性未知时，仍拒绝release接入，不能按“可选缓存”跳过。
